# Отчёт: переключатель языка Русский / English

Ветка `claude/i18n`. Русский остаётся основным языком исходников: ни одна русская строка в
`app.js`, `index.html` и `login.html` не переписана. Английский накладывается поверх, в духе
gettext: ключ перевода — сама русская строка.

## Что изменено в существующих файлах

Всего 7 строк, остальное — в новых файлах.

| Файл | Правка |
|---|---|
| `app/web/index.html` | `<script src="/i18n.js?v=1">` первым в `<head>` |
| `app/web/login.html` | то же |
| `app/api/main.py` | пути `/i18n.js` и `/manifest.<lang>.webmanifest` добавлены в `PUBLIC_EXACT`, вызов `i18n_api.register(app, store)` |

`app.js`, `styles.css`, `theme.js`, PWA-файлы, серверные сервисы и Telegram-бот не тронуты.
`LOGIN_FILES` тоже не тронут: тест `test_theme_js_is_public_on_its_own_route` сверяет его
целиком, поэтому пути i18n лежат в отдельном `app/api/i18n.py`.

Новые файлы:

| Файл | Что это |
|---|---|
| `app/web/i18n.js` | рантайм: выбор языка, переводчик DOM, `t()`, переключатели |
| `app/web/i18n/en.js` | английский словарь (1502 строки), шаблоны, контекстные переводы, CSS |
| `app/api/i18n.py` | публичный `/i18n.js`, переведённые манифесты, `/api/i18n/texts` (за сессией) |
| `scripts/i18n_extract.py` | сборщик русских строк из исходников, он же проверка покрытия |
| `tests/test_i18n.py` | 32 теста |
| `docs/i18n-check/` | скриншоты живой проверки (44 шт.), `report.json`, скрипт обхода `check_en.js` |

## Как устроено

### Загрузка

`/i18n.js` — публичный, как `/theme.js`. Его отдаёт сервер одним скриптом:
`app/web/i18n.js` + все `app/web/i18n/*.js` + `I18N.start()`. Заголовки: `no-cache` и ETag
(обычно ответ 304), сжатие через существующий `GZipMiddleware`. Внутри только тексты
интерфейса, о ферме ничего. Остальное по-прежнему закрыто: `/static/i18n.js`,
`/i18n/en.js` и `/api/i18n/texts` анониму отвечают 401 или 404 (это проверяют тесты).

### Выбор языка

* Хранится в `localStorage["forge-ops-lang"]`, в стиле `forge-ops-theme` и `forge-ops-sort`.
* Если выбора нет, язык берётся по первому узнаваемому языку из `navigator.languages`:
  * `ru, uk, be, kk, ky, uz, tg, hy, az` → русский;
  * язык, зарегистрированный файлом словаря (поле `match`), → он сам;
  * остальное → English.
* Переключатели:
  * в меню 👤 «Этот браузер», строка «Язык» сразу под темами;
  * на странице входа, под формой.

  Обе кнопки показывают название языка на нём самом (`translate="no"`).
* Смена применяется сразу, без перезагрузки:
  * DOM переводится или возвращается к оригиналам;
  * `<html lang>` и ссылка на манифест меняются;
  * canvas хронологии перерисовывается по событию `resize`.

  Проверено Playwright-ом: RU → EN → RU → EN, затем перезагрузка, язык сохраняется.

### Переводчик DOM

1. **Синхронно, в сеттерах `innerHTML` и `insertAdjacentHTML`.** app.js почти всё рисует через
   них и сразу меряет нарисованное: раскладку чипов (`balanceChips`), поповеры, подсказки.
   Перевод в момент вставки даёт этим замерам английский текст. Поэтому в `renderFleet`
   ничего вставлять не пришлось.
2. **`MutationObserver` на `document`** ловит остальное: `textContent`, `nodeValue`,
   `setAttribute`, новые узлы. Атрибуты: `title`, `placeholder`, `aria-label`, `alt` и
   атрибуты проекта `data-tip` (подсказки) и `data-l` (подписи ячеек на телефоне через CSS `attr()`).
3. **Без зацикливания.**
   * Для каждого узла и атрибута в `WeakMap` хранятся `{оригинал, показано}`. Если в узле
     ровно то, что записал переводчик, он его не трогает.
   * После своих записей вызывается `observer.takeRecords()`, так что собственные мутации
     переводчик не обрабатывает.
   * Записи нет, если перевод совпал с текстом.
   * Кэш: нормализованная строка → перевод (до 20 000 записей).
4. **Порядок поиска** (строка обрезана, внутренние пробелы схлопнуты, пробелы по краям
   сохраняются):
   1. точное совпадение (и вариант с другим регистром первой буквы: «Пауза» внутри «· пауза»);
   2. шаблоны языка: регулярки для чисел, порядка слов и т. п. Ключи с `%s` сами
      превращаются в шаблоны;
   3. тексты Bambu, полученные с сервера, если они встречаются внутри строки;
   4. известные куски внутри строки, самый длинный первым, на границах слов.
      Приложение склеивает тексты из фрагментов, например `"осталось " + время`.
      Строку с « · » переводчик пробует и целиком, и по частям, и берёт вариант, где меньше
      кириллицы;
   5. если после кусков русского осталось больше 30 % букв, строка остаётся как была. Это
      имя или незнакомый текст, полупереведённая каша хуже оригинала. Пример: «Принтер у окна»
      не превращается в «Printer у окна».
5. **Согласование числа.** `fix()` английского словаря правит «21 printer» → «21 printers».
   В русском 21 стоит в единственном числе.
6. **Контексты.** Одно русское слово в разных местах переводится по-разному. Ближайший
   предок, подходящий под селектор, решает:
   * «Пауза» — Paused (состояние) / Pause (команда в аудите и строке команды);
   * «Загрузка» — Load / Utilization (статистика);
   * «Действия» — Activity (вкладка) / Actions (заголовок столбца).
7. **Не переводятся:** `script`, `style`, `textarea`, `[translate=no]`, `.notranslate` и имена
   принтеров на карточке и в списках (`.pc-nm`, `.printer-name`, `.bd-name`, `.prk-name`).

### `t()` и граница браузерного API

`I18N.t(s)` — точечная функция для нового кода. Существующие места, куда DOM-перевод не
достаёт, переводятся на границе API браузера, а не в местах вызова. Причина: тесты проекта
сверяют эти строки app.js дословно, а часть функций исполняется в node без `I18N`.

| Что | Как |
|---|---|
| `alert` / `confirm` / `prompt` | в проекте их нет (это проверяет `test_web_confirm_ui`); единственный `.prompt()` — предложение установки PWA |
| `document.title` | собственный аксессор на `document`: в заголовок пишется перевод, app.js читает свой оригинал, поэтому его проверка `document.title !== t` не дёргает запись каждые 2 с |
| Уведомления браузера | `window.Notification` и `ServiceWorkerRegistration.prototype.showNotification` переводят заголовок и `body` |
| Canvas хронологии | `fillText`, `strokeText`, `measureText` переводят строки с кириллицей («сейчас»); `measureText` синхронен с `fillText`, обрезка имён считается по тому же тексту |
| `toLocale*("ru-RU")`, `localeCompare(x, "ru")` | обёртки `Date`, `Number`, `String.prototype` подменяют `ru`/`ru-RU` на локаль языка (`en-GB`: день перед месяцем, 24 ч); в русском режиме ничего не меняется |
| PWA-манифест | `/manifest.en.webmanifest` собирается сервером из `manifest.webmanifest` и словаря; ссылку в `<head>` меняет переключатель |
| CSS `content:` (`пауз `, `вход: `) | поле `css` словаря, внутри тех же `@media`, с селектором `:root[lang="en"]` |

### Тексты сервера

* Ошибки API, ответы команд, подписи этапов печати и состояний, причины журнала автосушки,
  подсказки уведомлений собраны скриптом из 14 серверных модулей: 363 уникальные строки
  (`printer_commands.py`, `ams_autodry*.py`, `notification_actions.py`, `admin.py`,
  `normalizer.py` и др.). Они в том же словаре.
* Тексты HMS и print_error Bambu на сервере русские (из таблиц Bambu). Для EN сервер отдаёт
  **английские оригиналы Bambu**, а не перевод: берёт их из вендоренных таблиц ha-bambulab
  (`app/vendor/pybambu/hms_error_text/hms_en.json.gz`) по коду.
  * `POST /api/i18n/texts?lang=en` (за сессией) возвращает `{русский текст: English}` для
    текущих уведомлений парка и для строк, которые клиент встретил и не смог перевести.
    Это причины пауз и ошибок в журнале печатей и статистике, коды автопропуска. Сервер
    находит их обратным поиском по тем же таблицам, принимает не больше 200 строк по
    2000 символов.
  * Клиент спрашивает, только когда встретил новую непереводимую строку: debounce 600 мс,
    не чаще раза в 3 с, каждую строку один раз. Получив ответ, он переводит экран заново
    от оригиналов.
  * Каталог HMS в рантайме (`hms_catalog.py`) скачивает у Bambu только `lang=ru`. Коды,
    которых нет в вендоренной английской таблице, в EN останутся русскими (см. ниже).

## Сколько переведено

Сборщик `scripts/i18n_extract.py` разбирает исходники, а не грепает их:
* в app.js — JS-токенайзер: строки, шаблонные литералы, без комментариев и регулярок;
* в HTML — `HTMLParser`;
* в Python — `ast`, без докстрингов и вызовов `logger.*`.

Литерал режется на видимые куски: текст между тегами и значения атрибутов, включая обрывки
вида `'" data-tip="Загрузить: '`.

| Источник | Уникальных русских строк |
|---|---|
| `app.js` | 1025 |
| `index.html` | 251 |
| `login.html` | 8 |
| `i18n.js` (подпись «Язык», «Русский») | 2 |
| PWA-манифест | 5 |
| серверные модули | 363 |
| **Всего** (без повторов между файлами) | **1511** |

* 1502 строки в словаре.
* 9 исключены с причиной (`untranslated`):
  * 6 регулярок `job_journal.py`, которые разбирают русский текст ошибок на сервере;
  * 2 значения `data-dirty`, их никто не показывает;
  * «Русский» — имя языка в переключателе.
* Шаблонов 9, ещё 3 строки с `%s` работают как шаблоны автоматически.

Переводили в терминах Bambu Studio / OrcaSlicer: nozzle, bed, chamber, filament, AMS, Pause /
Resume / Stop, Load / Unload, Auto-dry, Bed down. Глоссарий для консистентности был общий на
все части.

* **Ошибки JS:** 0. В консоли страницы входа без сессии есть одна сетевая запись

## Что осталось на русском и почему

1. **Данные пользователя:** имена принтеров и пользователей, имена файлов заданий, заметки
   обслуживания, шаблоны Telegram. Это не интерфейс.
2. **Выгрузка CSV журнала печатей** (`/api/history/jobs.csv`): заголовки столбцов формирует
   сервер (`job_queries.py`), файл не проходит через DOM. Переводы заголовков в словаре уже
   есть. Чтобы включить, нужно передать `lang` в запрос и подставить словарь на сервере
   (`i18n_api.strings("en")`).
3. **Тексты HMS, которых нет в вендоренной английской таблице ha-bambulab.** Их знает только
   рантайм-каталог Bambu, а он скачивается с `lang=ru`. Чтобы закрыть: в `hms_catalog.py`
   качать вторую таблицу `query.php?lang=en` (файл `text_en_<P>.json`) и отдавать её в
   `asked_texts`. На демо-ферме таких не встретилось.
4. **Числа, которые app.js форматирует сам:** коэффициент «факт / план» `×1,00` (десятичная
   запятая через `toFixed().replace(".", ",")`) и даты вида `01.11` (собраны вручную, не через
   `toLocale*`). Они понятны, но не по-английски. Исправить можно только в app.js, это вне
   рамок «минимум правок».
5. **Telegram-бот** — по заданию не трогали (см. ниже).
6. **Неизвестные будущие строки.** Если в app.js появится новая строка без словаря, её покажут
   как есть. Тест покрытия упадёт и назовёт файл и строку.

Тонкости, которые стоит знать при переносе во внутреннюю версию:
* Перевод по кускам рассчитан на склейки app.js. Короткие куски («с», «из», «на», «до») при
  подстановке берутся только на границах слов. Правило «больше 30 % кириллицы — не трогать»
  не даёт испортить незнакомый текст.
* Обёртки `toLocale*` и `localeCompare` меняют только аргумент `"ru"` / `"ru-RU"` и только
  при не-русском языке.
* Демо-сервер для проверки в репозиторий не положен: это стенд, а не часть продукта. Скрипт
  обхода `docs/i18n-check/check_en.js` работает против любой запущенной панели
  (`node check_en.js http://host:port out-dir`; логин и пароль заданы в скрипте).

## Как добавить третий язык одним файлом

1. Скопировать `app/web/i18n/en.js` в `app/web/i18n/<код>.js`, например `de.js`, и заменить:
   * `I18N.register("de", { name: "Deutsch", locale: "de-DE", match: ["de"], ... })`;
   * значения в блоке `strings` между `/*strings:begin*/` и `/*strings:end*/` — блок должен
     остаться чистым JSON, сервер читает его для манифеста;
   * `patterns`, `contexts`, `fix` (согласование числа своего языка), `css`.
2. Перезапустить сервер. Он сам найдёт файл:
   * добавит его в `/i18n.js`;
   * откроет `/manifest.de.webmanifest`;
   * переключатели в 👤 и на странице входа покажут «Deutsch»;
   * `navigator.languages` с `de` выберет его.
3. `pytest tests/test_i18n.py` проверит покрытие нового файла тем же сборщиком. Недостающие
   строки покажет `python scripts/i18n_extract.py --missing de`.

Английские оригиналы HMS есть только для `en`. Для другого языка `/api/i18n/texts` вернёт `{}`,
тексты Bambu останутся русскими, пока не скачана таблица Bambu на этом языке (`query.php`
поддерживает `lang=de` и др.).

## Telegram-бот: как перевести (не сделано, по заданию)

Тексты бота собираются на сервере: сводка в `main.py` («— на обслуживании», `5ч30м`, иконки
состояний), уведомления о событиях — по шаблонам из настроек, команды и ответы — в
`telegram_bot_async.py`. План:

1. Настройка `telegram_lang` (`ru` | `en`) в `settings_service`, выбор в «Админ → Система →
   Telegram».
2. Серверный переводчик `app/services/i18n.py`:
   * словарь — тот же `app/web/i18n/<lang>.js` через `app.api.i18n.strings(lang)`, второй
