# Отчёт: сайт документации Kuznitsa

Ветка `claude/docs-site`. Документация описывает версию 2.0.0 (коммит `313ccae`).

## Что сделано

**Новые файлы.** Все они лежат в `docs-site/`, кроме workflow:

- `mkdocs.yml` — настройки MkDocs Material и плагина `mkdocs-static-i18n`:
  - английский — язык по умолчанию, в корне сайта; русский — в `/ru/`;
  - значок смены языка в шапке;
  - светлая и тёмная тема с переключателем;
  - поиск по обоим языкам (`lang: [en, ru]`, со стеммингом для русского);
  - переведены пункты навигации;
  - включена строгая проверка ссылок и якорей;
  - якоря у русских заголовков сохраняют кириллицу.
- `requirements.txt` — точные версии: `mkdocs==1.6.1`, `mkdocs-material==9.8.0`,
  `mkdocs-static-i18n==1.3.1`. Остальные зависимости тоже закреплены (`pip freeze`), проверено на
  Python 3.13.
- `docs/en/…` и `docs/ru/…` — 17 страниц на каждом языке с одинаковыми именами файлов. Тексты
  написаны заново на каждом языке, а не переведены дословно.
  - В английской версии названия кнопок и экранов даны по-английски, а русское название из
    интерфейса — в скобках.
  - В русской версии названия взяты из интерфейса как есть.
- `.gitignore` — исключает папку `site/`.
- `.github/workflows/docs.yml` — строит сайт командой `mkdocs build --strict` и публикует его через
  `actions/upload-pages-artifact` и `actions/deploy-pages`. Запускается:
  - при push в `main`, если изменились `docs-site/**` или сам workflow;
  - вручную (`workflow_dispatch`).
- `README.md` — добавлена одна строка со ссылкой на сайт. Больше вне `docs-site/` ничего не
  менялось.

**Разделы сайта.** Номера — пункты задания.

**Как сделаны ссылки.**

- Скриншоты вставлены ссылками на файлы в репозитории
  (`raw.githubusercontent.com/…/main/docs/screenshots/…`), а не скопированы.
- Ссылки на код ведут на конкретный коммит `313ccae…`. Так номера строк не уедут, когда код
  изменится.

**Проверки.**

- `mkdocs build --strict` проходит без ошибок и предупреждений. Проверено дважды, второй раз — в
  чистом окружении, где пакеты поставлены из `requirements.txt`.
- Отдельный скрипт прошёл по всем 37 собранным HTML-страницам. Все внутренние ссылки и якоря
  существуют.
- На каждой странице переключатель языка ведёт на ту же страницу другого языка.
- Собранный сайт я открыл в Chromium по пути `/printer-fleet-dashboard/`, как он будет лежать на
  Pages:
  - переключатель языка на четырёх страницах (главная, Telegram, AMS, Docker) ведёт на ту же
    страницу другого языка и обратно;
  - поиск находит результаты и на русском («прокси», «принтер», «автосушка»), и на английском
    («proxy»);
  - тёмная тема включается.

## Чего не нашёл в коде (поэтому не описано или описано как «нет»)

- **OBS-оверлеев нет.** Нет ни страницы для OBS, ни виджета, ни встраивания.
  - Слово «OBS» встречается только в комментарии `app/collectors/bambu_collector.py:91`.
  - Трансляция с камер удалена: `/api/cameras` — заглушка, `app/api/main.py:593`.
- **Установщика и автозапуска для Windows нет.** Файл `main.spec` (PyInstaller) есть, но готовой
  сборки и инструкции к ней нет, поэтому я его не описывал.
- **Push-уведомлений через service worker нет.** В README сказано «browser push notifications»,
  но в `app/web/pwa/sw.js` нет обработчика push. Уведомления показывает сама открытая страница
  (опрос каждые 3 с). В документации написано честно: они работают, только пока вкладка открыта,
  и только по HTTPS.
- **Поля для API-ключа Moonraker нет.** Moonraker должен пускать компьютер с панелью без ключа.
- **Сброса забытого пароля администратора нет.** В FAQ описан выход, который следует из кода:
  убрать `users.db` — тогда при старте создастся новый `admin`.
- **Кнопок «Годно / Брак» больше нет.** API `PUT /api/admin/history/jobs/{id}/verdict` остался, но
  интерфейс его не вызывает. Не описывал.
- **Подсказки, где на экране Bambu найти серийный номер, нет.** В форме есть подсказка только для
  кода доступа («Экран принтера → Настройки → Сеть»), поэтому место серийного номера на экране
  принтера я не указывал.

## Расхождения между кодом и README / подсказками — стоит поправить

В документации везде описано **фактическое поведение кода**.

1. **Telegram, пустой «Разрешённый ID чата».**
   - Подсказка в интерфейсе (`app/web/index.html:528`) говорит: «Пусто — без ограничения».
   - На деле при пустом поле бот отклоняет **любой** чат (`telegram_bot_async.py:254`), и
     уведомления не уходят.
   - В документации поле описано как обязательное. Там же объяснено, как узнать ID: из строки
     `Denied chat …` в журнале.
   - Похоже на ошибку в коде или в подсказке.
2. **«Закреплённая сводка»** (`app/web/index.html:533`). Бот не закрепляет сообщение, а только
   редактирует его. В документации написано: «закрепить можно самостоятельно».
3. **`.env` программа не читает.** `python-dotenv` в коде нет. При этом в README есть шаг
   `cp .env.example .env  # optional`. В документации объяснено, как задавать переменные для каждого
   способа установки.
4. **Устаревшие названия разделов.** Сейчас они называются «Админ → Парк» и «Админ → Система».
   - В `.env.example` (строки 50, 61–63) — «Admin → Printers», «Settings → Telegram»,
     «Settings → Proxy».
   - В `docker-compose.yml:10` — «Admin → Printers».
   - В комментариях `config.py` — тоже старые названия.
5. **README:180** говорит, что у `printer_light_disabled` «нет интерфейса». В 2.0.0 он есть —
   галочка «Разрешить управление светом» в форме Creality.
6. **`POLL_INTERVAL`.** В README и `.env.example` по умолчанию указано `5`, но `main.py:49`
   поднимает любое значение до 30 с. В документации так и написано.
7. **Три переменные окружения читаются кодом, но отсутствуют в `.env.example` и README:**
   `HISTORY_RETENTION_DAYS`, `JOBS_RETENTION_DAYS`, `FORGE_TZ_OFFSET_MIN`. В документацию добавлены.
8. **Docker.**
   - `docker-compose.yml` не монтирует `ams_history.db`, поэтому история AMS теряется при
     пересоздании контейнера. В документации предложена дополнительная строка `volumes`.
   - README:129 советует `docker compose pull`, но опубликованного образа нет: образ собирается
     локально.
9. **`deploy/setup_https.sh` и `deploy/nginx-bambu.conf` не стыкуются.**
   - Скрипт создаёт самоподписанный сертификат в `/etc/ssl/bambu/` и копирует conf без изменений.
   - А conf проксирует на `127.0.0.1:58000` (это порт туннеля), берёт сертификат Let's Encrypt и
     слушает 8443.
   - В итоге, как есть, локальный HTTPS не заработает.
   - Скрипт обещает `https://<IP>` без порта (строка 77) и «старый HTTP-адрес работает»
     (строка 76). Второе верно, только если задано `WEB_HOST=0.0.0.0`.
   - В документации описаны нужные правки conf: `proxy_pass` на 8000, пути к сертификату и порт
     8443.
10. **`deploy/bambudiagnostic.service`** запускает системный `python3`, а README предлагает ставить
    зависимости в `.venv`. В документации описана правка `ExecStart`.
11. **«Применить и перезапустить» на Windows.** Процесс завершается через `os._exit(1)`
    (`app/api/admin.py`, `apply_printer_changes`), а перезапускать его некому. В документации есть
    предупреждение.
12. **Автопропуск ошибок включён из коробки.** Коды `0500_8062` и `0C00_8009` действуют на всех
    Bambu (это видно по `settings_service.py`). Это решение под ферму владельца («стёртые метки»).
    Для чужих пользователей такое поведение неожиданно. В документации оно выделено на нескольких
    страницах. Возможно, стоит сделать список пустым по умолчанию.
13. **Часовой пояс автосушки по умолчанию — МСК** (`FORGE_TZ_OFFSET_MIN=180`). Для англоязычных
    пользователей это неочевидно; в документации описано.
14. **Сообщения сервера на английском.** Ошибки на странице входа и часть ошибок админки
    (`Invalid username or password`, `Password must be at least 8 characters`) приходят на
    английском, хотя интерфейс русский. Описано в первом запуске и в FAQ.
15. **Нет контакта для коммерческой лицензии.** В `COMMERCIAL-LICENSE.md:26` стоит заглушка
    `<add your contact email / URL here>`, а на этот файл ссылаются страница «Лицензия» и
    `SECURITY.md`. **Нужно вписать контакт.**
16. **Адрес репозитория в README.** В Quick start написано `<your-fork-url>`. Документация везде
    использует настоящий адрес `https://github.com/mihey-web/printer-fleet-dashboard.git`.

## Что проверить владельцу

1. **Включить Pages.** Settings → Pages → Build and deployment → Source: **GitHub Actions**. Без
   этого `deploy-pages` упадёт. Workflow запустится после слияния в `main` (или вручную, из вкладки
   Actions).
2. **Bambu.**
   - Формулировки про LAN Mode и Developer Mode: насколько точно они описывают реальные модели и
     прошивки?
   - Подсказка о коде доступа взята из формы.
3. **Klipper.** Верно ли, что без `trusted_clients` и без ключа Moonraker не пустит панель? Это
   вывод из того, что поля для ключа нет.
4. **HTTPS с самоподписанным сертификатом.** Работают ли на нём уведомления браузера и установка
   PWA? В документации написано осторожно: «некоторые браузеры могут не дать».
5. **Установка не прогонялась на реальных системах.** Шаги для Windows и Raspberry Pi OS написаны
   по коду и файлам `deploy/`. Хорошо бы один раз пройти их вживую.
6. **Английские названия экранов и кнопок.** Я перевёл их сам, например «Парк» → Fleet,
   «Автоматика» → Automation, «Зритель» → Viewer, «Пробный режим» → Trial mode. Параллельная
   сессия делает переключатель RU/EN в самой панели. Когда появится английский интерфейс, сверьте
   термины и поправьте документацию под его надписи.
7. **Ссылки на код закреплены за коммитом 2.0.0** (`313ccae`). После изменений кода их нужно будет
   обновить.
8. **Мелкие предупреждения.**
   - При сборке Material for MkDocs выводит сообщение о конце поддержки (май 2027) и называет
     преемника — Zensical. В CI это сообщение отключено через `NO_MKDOCS_2_WARNING=1`. На
     `--strict` оно не влияет.
   - При локальной проверке переключатель языка запрашивал `sitemap.xml` по неверному
     относительному пути (404). На работу переключения это не влияет; на Pages стоит взглянуть.

## Как собрать локально

```bash
cd docs-site
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
mkdocs serve          # http://127.0.0.1:8000/printer-fleet-dashboard/
mkdocs build --strict
```
