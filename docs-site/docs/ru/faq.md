# Вопросы и неполадки

## Где журнал?

Большинство ответов начинается с журнала.

| Способ установки | Команда / место |
| --- | --- |
| Windows | окно Командной строки, где запущен `python main.py` |
| Linux / systemd | `sudo journalctl -u bambudiagnostic.service -f` |
| Docker | `docker compose logs -f` |

## Вход и доступ

### После входа страница снова просит пароль {#login-loops}

Браузер отбросил cookie входа. По умолчанию (`COOKIE_SECURE=1`) cookie передаётся только по HTTPS.
Если вы открываете панель по `http://<адрес>:8000` с другого устройства, то либо:

- задайте `COOKIE_SECURE=0` (только в доверенной локальной сети), либо
- настройте [HTTPS через nginx](security.md#https-nginx) и оставьте `COOKIE_SECURE=1`.

В файлах Docker `COOKIE_SECURE=0` уже задано.

### Панель не открывается с телефона или другого компьютера

По умолчанию она слушает только компьютер, на котором запущена (`WEB_HOST=127.0.0.1`). Задайте
`WEB_HOST=0.0.0.0` (и `COOKIE_SECURE=0` для обычного HTTP) или поставьте перед ней nginx. Проверьте
также брандмауэр компьютера для порта 8000.

### Потерял пароль первого запуска

Посмотрите журнал ещё раз — пароль печатается при первом запуске (см. таблицу выше). Если журнала
уже нет и другого администратора нет, кнопки сброса нет. Администратор создаётся, только когда база
пользователей пуста, поэтому можно:

1. остановить панель;
2. вынести `users.db` из папки проекта (сохраните его как копию);
3. запустить панель — будет создан новый `admin`, а его пароль напечатан в журнал.

Это удаляет **все** учётные записи, журнал действий и ключ сеансов (выйдут все). Принтеры, настройки
и история лежат в `printer_history.db` и не пострадают.

### При входе пишет `Too many login attempts. Try again later.`

Слишком много неверных паролей за 15 минут (5 с одного адреса или 10 для одного логина). Подождите
15 минут. См. [Сеансы и защита входа](security.md#sessions).

### Часть сообщений на английском

Интерфейс на русском, но некоторые сообщения приходят с сервера на английском — на странице входа и
в некоторых формах админки (например, `Password must be at least 8 characters`).

## Принтеры

### Добавленный принтер не появляется

Изменения списка принтеров вступают в силу только после **«Применить и перезапустить»** в «Админ →
Парк». До этого висит жёлтая полоса «Есть непримененные изменения».

### После «Применить и перезапустить» панель пропала (Windows)

Кнопка завершает программу, чтобы её перезапустил диспетчер служб. На Windows его нет — снова
выполните `python main.py`. Если на Linux или в Docker страница пишет «Сервис не поднялся за 90 сек
— проверь вручную», посмотрите журнал.

### Принтер «Офлайн»

- Достаёт ли компьютер с панелью до IP принтера? Проверьте порт: Bambu 8883, Creality 9999,
  Moonraker 7125, MKS WiFi 8080 (или тот, что вы указали).
- **Bambu:** включён ли на принтере режим LAN, верны ли код доступа и серийный номер? Ошибки
  подключения видны в журнале.
- **Klipper:** в форме нет поля для API-ключа, поэтому Moonraker должен пускать компьютер с
  панелью без ключа.
- Короткие пропадания скрываются: после неудачного опроса карточка около 3 минут держит последние
  данные и только потом становится «Офлайн».

### На карточке Bambu только кнопка света и замок 🔒

Принтер отклоняет неподписанные команды управления. Причина — в подсказке замка; «прошивка блокирует
(нет Developer Mode)» значит, что новые прошивки принимают такие команды только в Developer Mode.
Наблюдение продолжает работать. См. [Добавление принтеров → Bambu Lab](printers.md#bambu-lab).

### Кнопок управления нет совсем

- Вы вошли как «Зритель» — управление видят только администраторы.
- Принтер офлайн.
- Это принтер MKS WiFi — для них только наблюдение.

### Принтеры Bambu сами продолжают печать после ошибки «метка на пластине»

Это **«Автопропуск ошибок»**: из коробки панель нажимает «Игнорировать и продолжить» для кодов
0500_8062 и 0C00_8009 на всех принтерах Bambu. Если это не нужно, уберите коды в
[«Админ → Автоматика»](interface/admin.md#auto-skip-errors).

## Уведомления

### Telegram молчит

Заполните **«Разрешённый ID чата»** — в версии 2.0.0 при пустом поле бот игнорирует любой чат. См.
[Telegram → Если бот молчит](telegram.md#bot-silent).

### Уведомления браузера не работают

Они работают только по HTTPS и только пока панель открыта во вкладке браузера, и их нужно разрешить,
когда браузер спросит. См. [Обзор интерфейса](interface/index.md#this-browser).

### Не получается установить панель как приложение

Браузер предлагает установку только на HTTPS-адресе. См.
[Телефон и приложение](interface/mobile-pwa.md#install-pwa).

## AMS

### Автосушка никогда не запускает сушку

- Из коробки она в **«Пробном режиме»** и только пишет журнал. Выключите пробный режим в
  [«Админ → Автоматика»](interface/admin.md#ams-auto-drying).
- Проверьте **«Окно запуска»** и переключатель **«Авто»** у блока.
- Удалённая сушка — для AMS 2 Pro и AMS HT; принтеры на обслуживании пропускаются.
- **«Журнал сушки»** на экране «AMS» объясняет, почему автосушка решила так.

### Ночное окно автосушки работает не в те часы

Время фермы — московское (UTC+3), если не задан `FORGE_TZ_OFFSET_MIN` — см.
[Настройки](configuration.md#history-automation).

### История AMS пропала после обновления Docker

`docker-compose.yml` не сохраняет `ams_history.db` вне контейнера. Какую строку добавить — см.
[Docker](install/docker.md#settings).

## Данные

### Как сделать копию или перенести панель?

Скопируйте `printer_history.db`, `users.db` и `ams_history.db` из папки проекта, пока панель
остановлена, и положите их в папку новой установки. Для Linux есть готовое
[ночное резервное копирование](install/linux.md#backup).

### Страница не загружается, когда `main.py` запущен из другой папки

Программа берёт свои веб-файлы из папки `app/web` относительно текущей папки. Всегда запускайте её
из папки проекта (сначала `cd kuznitsa`). Служба systemd и Docker так и делают.
