# Установка через Docker

В репозитории есть `Dockerfile` и `docker-compose.yml`, поэтому на компьютере с Docker и Docker
Compose панель запускается несколькими командами. Образ собирается на вашем компьютере из
исходного кода.

## Запуск

```bash
git clone https://github.com/mihey-web/printer-fleet-dashboard.git kuznitsa
cd kuznitsa
touch printer_history.db users.db ams_history.db   # чтобы Docker подключил их как файлы
docker compose up -d --build
docker compose logs -f                 # один раз прочитать пароль администратора
```

Строка с `touch` важна: она создаёт три пустых файла баз, чтобы Docker подключил их в контейнер
именно как файлы, а данные оставались на компьютере.

Откройте `http://<адрес компьютера>:8000` и войдите как `admin` с паролем из журнала
(см. [Первый запуск](first-run.md)). Нажмите ++ctrl+c++, чтобы перестать смотреть журнал, — панель
продолжит работать.

## Что настраивает `docker-compose.yml`

- Контейнер называется `kuznitsa` и сам перезапускается (`restart: unless-stopped`) — так же
  **«Применить и перезапустить»** возвращает его после изменения списка принтеров.
- Порт `8000` компьютера — это панель. Он открыт на **всех** сетевых интерфейсах, а Docker
  добавляет свои правила брандмауэра, поэтому **ufw / firewalld его не закрывают**. Для домашней
  сети это нормально; как оставить порт только на этом компьютере — в разделе
  [За nginx или Caddy](#behind-nginx-or-caddy).
- `COOKIE_SECURE=0`, потому что по обычному HTTP в вашей сети cookie входа иначе отбрасывается. Если
  поставите панель за HTTPS (nginx, Caddy), задайте `1` и открывайте панель только через прокси.
- Файлы `printer_history.db`, `users.db` и `ams_history.db` из папки проекта подключены в
  контейнер, поэтому список принтеров, настройки, история, пользователи и история влажности AMS (по
  ней работает автосушка) переживают обновления.

## Настройки {#settings}

Добавляйте переменные в список `environment:` в `docker-compose.yml`. В файле уже есть
закомментированные примеры для первого администратора и ключа сеансов:

```yaml
    environment:
      - WEB_HOST=0.0.0.0
      - WEB_PORT=8000
      - COOKIE_SECURE=0
      # - FORGE_ADMIN_USERNAME=admin
      # - FORGE_ADMIN_PASSWORD=change-me-immediately
      # - FORGE_JWT_SECRET=your-64-hex-chars
```

Уберите `#`, чтобы строка заработала, и снова выполните `docker compose up -d`. Все переменные — в
разделе [Настройки и переменные окружения](../configuration.md).

## За nginx или Caddy на том же компьютере {#behind-nginx-or-caddy}

Если nginx или Caddy на этом компьютере отдаёт панель по HTTPS, поменяйте в `docker-compose.yml` три
вещи:

1. Откройте порт только на этом компьютере, чтобы к панели можно было попасть только через прокси:

    ```yaml
        ports:
          - "127.0.0.1:8000:8000"
    ```

2. Задайте `COOKIE_SECURE=1`.
3. Разрешите адрес прокси. Прокси подключается к опубликованному порту, поэтому внутри контейнера
   каждый запрос приходит со шлюза сети Docker (например, `172.18.0.1`), а не с `127.0.0.1`. Найдите
   его в журнале — это адрес в начале каждой строки запроса:

    ```bash
    docker compose logs | grep '"GET /'
    ```

    и добавьте:

    ```yaml
          - FORGE_TRUSTED_PROXIES=172.18.0.1
    ```

Без шага 3 панель не верит адресу посетителя, который передаёт прокси, и считает всех одним
адресом: пять неверных паролей от кого угодно закрывают вход всем на 15 минут, а в журнале действий
вместо настоящих адресов стоит шлюз. Разрешайте только тот адрес, с которого действительно приходит
прокси: кто подключается с доверенного адреса, может назвать любой адрес посетителя. Целая сеть
вроде `172.16.0.0/12` заодно доверяет всем остальным контейнерам на компьютере.

## Обновление

```bash
cd kuznitsa
git pull
touch printer_history.db users.db ams_history.db   # существующие файлы не меняются
docker compose up -d --build
```

Версии до этой не подключали `ams_history.db`. Без строки с `touch` Docker создаст *папку* с этим
именем, и панель остановится с `… a directory, not a database file` в журнале: остановите её,
удалите пустую папку, выполните `touch ams_history.db` и запустите снова. Чтобы сохранить историю
AMS из старого контейнера, скопируйте её **до** `docker compose up -d --build`, вместо `touch` для
этого файла (последние минуты могут не попасть):

```bash
docker compose stop
docker cp kuznitsa:/app/ams_history.db ./ams_history.db
```

## Полезные команды

| Что | Команда |
| --- | --- |
| Смотреть журнал | `docker compose logs -f` |
| Остановить | `docker compose down` |
| Запустить снова | `docker compose up -d` |
