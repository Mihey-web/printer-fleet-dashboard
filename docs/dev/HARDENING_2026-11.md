# Установка у себя: доводка — ноябрь 2026

Ветка `claude/install-hardening`, от `main` (коммит `fbe485c`, после релиза 2.1.0).
Закрывает разделы «Найдено, но оставлено» и «README обещает то, чего в коде нет» из
[`REVIEW_2026-11.md`](REVIEW_2026-11.md) — то, на что наткнётся человек, который ставит панель у себя.
Проверялось кодом, тестами и живым запуском `main.py` в контейнере. Без реальных принтеров, без Docker
и без nginx: их в этой среде нет.

## Коротко

1. Сделано шесть пунктов. `FORGE_TRUSTED_PROXIES` (IP и CIDR). Встроенный загрузчик `.env` без новых
   зависимостей. Подсказка на странице входа и строка в журнале, когда `COOKIE_SECURE=1` по `http://`.
   `ams_history.db` смонтирована в `docker-compose.yml`, в README есть предупреждение про порт 8000 и ufw.
   Прогрессивная задержка 1→30 с на имя пользователя. В README в разделе тестов добавлен `httpx`.
2. Тесты: на `main` было **2952 прошли, 0 упали**, стало **2986 прошли, 0 упали**. Прибавилось 34 теста
   в `tests/test_hardening_2026_11.py`. На старом коде 26 из них не проходят (20 падают, 6 с ошибкой
   фикстуры), 8 проходят: эти проверяют, что прежнее поведение не сломалось. Три старых теста входа
   переписаны под асинхронный `login`, их ожидания прежние.
3. Живая проверка. `python main.py` запускался в копии проекта с `.env`. Журнал показал `.env: set …`,
   предупреждение про `COOKIE_SECURE` и пропуск ошибочной записи в `FORGE_TRUSTED_PROXIES`. Настоящий
   Chromium вошёл по `http://<адрес в сети>` при `COOKIE_SECURE=1`: cookie не сохранились, подсказка
   показалась по-русски и по-английски. Через curl: после 10 ошибок для `admin` верный пароль вошёл
   за 1,27 с вместо мгновенно, адреса за доверенным прокси различаются. Сайт документации собирается
   `mkdocs build --strict` без ошибок.
4. Что осталось. Задержка не ограничивает **параллельный** подбор: N одновременных попыток ждут
   одинаково и проверяются вместе. Потолок даёт только лимит по IP (5 за 15 минут с адреса).
   Ограничить и параллельный подбор, не дав при этом запереть владельца, можно только решением
   владельца: второй фактор или разблокировка из консоли. Подробности ниже.
5. Docker, nginx и Caddy здесь не запускались. Адрес шлюза моста и поведение `docker compose`
   описаны по документации Docker, на живом хосте их стоит проверить один раз.

## Что сделано

### 1. Доверенные прокси — `FORGE_TRUSTED_PROXIES`

- `config.py`: `TRUSTED_PROXIES` — список из `FORGE_TRUSTED_PROXIES` (через запятую). По умолчанию
  `127.0.0.1,::1`, как было. `create_app` уже передавал `config.TRUSTED_PROXIES` в `init_auth`.
- `app/api/auth.py`: записи разбираются в `ipaddress.ip_network`, поэтому годятся и адрес
  (`172.18.0.1`), и сеть (`172.16.0.0/12`). Неверная запись пропускается с предупреждением в журнал:
  опечатка не роняет сервер и не расширяет доверие. Адрес вида `::ffff:127.0.0.1` (двойной стек)
  сравнивается как IPv4. Не-IP (`unknown`, `testclient`) не доверяется. Логика выбора адреса из
  `X-Real-IP` / `X-Forwarded-For` (исправление f1) не менялась.
- Документация: README (Docker behind nginx/Caddy), `docker-compose.yml` (закомментированная строка
  с объяснением), сайт `install/docker.md` — раздел «За nginx или Caddy на том же компьютере»
  (`#behind-nginx-or-caddy`), строка в таблице `configuration.md`, абзац в `security.md`, ссылка из FAQ.
  Как найти адрес шлюза: в журнале доступа uvicorn (`docker compose logs | grep '"GET /'`).
  Отдельно предупреждаю, что сеть `172.16.0.0/12` доверяет и всем соседним контейнерам.

### 2. Файл `.env`

- `app/services/env_file.py` — около 60 строк, только стандартная библиотека. Формат: `KEY=VALUE`,
  `export KEY=…`, `#`-комментарии (в начале строки и после значения через пробел), кавычки `'…'` /
  `"…"` (буквально, без экранирования), BOM от Блокнота. Кривые строки пропускаются; при повторе
  ключа берётся последний.
- Ставятся только ключи, которых **нет** в окружении: systemd `Environment=`, `environment:` в
  Docker, `set` / `export` главнее. В журнал пишутся только имена (`.env: set WEB_HOST, …`),
  значения никогда.
- `main.py` читает `.env` из своей папки до импорта приложения. Это важно: `state_store`, `ams_store`,
  `printer_commands`, `config` читают окружение при импорте. Чтение идёт только при запуске как
  программы (`__name__ == '__main__'`): тесты, которые делают `import main`, `.env` разработчика не
  подхватывают.
- `.env.example` сверен с кодом. Добавлены `FORGE_TRUSTED_PROXIES`, `HISTORY_RETENTION_DAYS`,
  `JOBS_RETENTION_DAYS`, `FORGE_TZ_OFFSET_MIN`; у `POLL_INTERVAL` указан минимум 30 с; шапка
  объясняет порядок приоритета. Тест `test_env_example_lists_exactly_what_the_code_reads` ищет в коде
  `os.environ.get("…")`, `_env_int("…")`, `_env_days("…")` и требует точного совпадения с
  `.env.example`: новая переменная без строки в примере уронит тест.
- `.dockerignore` уже исключал `.env`, так что в образ файл не попадает. В Docker настройки по-прежнему
  задаются через `environment:`.
- Документация: README («From source»), сайт `configuration.md` и `install/windows.md` — вместо
  «программа `.env` не читает».

### 3. Вход по HTTP при `COOKIE_SECURE=1`

- `app/web/login.html`: если вход ответил 200 и страница открыта по `http:`, она спрашивает
  `/api/auth/me`. Если сессии нет, пишет: «Вход принят, но браузер отклонил cookie: откройте панель
  по HTTPS или задайте COOKIE_SECURE=0 в локальной сети.» и остаётся на форме, без перехода. По
  `https:` лишнего запроса нет. Строка добавлена в конец словаря `app/web/i18n/en.js`,
  `tests/test_i18n.py` проходит.
- `main.py`: одна строка `WARNING` при старте, если `COOKIE_SECURE=1`, а `WEB_HOST` не loopback
  (`0.0.0.0`, адрес в сети). За HTTPS-прокси на том же хосте панель слушает `127.0.0.1`, там
  предупреждения нет. В Docker за прокси (`WEB_HOST=0.0.0.0` внутри контейнера, `COOKIE_SECURE=1`)
  строка появится зря, поэтому она написана условно: «если открываете по http://…».
- Тесты гоняют настоящий скрипт страницы в node с заглушками `fetch` / `location` (http + нет
  сессии, http + сессия есть, https, неверный пароль).

### 4. Docker

- `docker-compose.yml`: смонтирована `./ams_history.db:/app/ams_history.db`; в строке `touch`
  теперь три файла. Тест сверяет: каждая база, которую открывает приложение (`state_store`,
  `users.db`, `ams_store`), смонтирована и создаётся через `touch`.
- Обновление со старой версии. Кто сделает `git pull && docker compose up -d --build` без
  `touch ams_history.db`, получит от Docker **папку** с этим именем. Раньше это падало бы на старте
  с невнятным `unable to open database file`. Теперь `main()` проверяет все три пути и выходит с
  понятной строкой (`… a directory, not a database file … run touch <file>`). В README и в
  `install/docker.md` (раздел «Обновление») `touch` стоит перед `up`; там же написано, как
  забрать старую историю AMS из контейнера (`docker compose stop` + `docker cp`).
- README и `docker-compose.yml`: абзац о том, что порт 8000 открыт на всех интерфейсах, Docker
  обходит ufw / firewalld и что за прокси надо публиковать `127.0.0.1:8000:8000`. То же — на сайте.

### 5. Подбор пароля с многих IP: прогрессивная задержка по имени

- `app/api/auth.py`. `login` стал `async`. Сначала в пуле потоков считаются неудачи по имени за
  15 минут. Если их 10 и больше, попытка ждёт `asyncio.sleep(1, 2, 4, 8, 16, 30, 30 …)`. Потом в пул
  потоков уходит прежняя проверка (`_login_checked`): блокировка по IP, лимит 5 с адреса, bcrypt,
  запись неудачи. Поэтому ожидание не держит ни поток, ни event loop, ни блокировку по IP.
- Задержка действует на любую попытку под этим именем, с верным паролем тоже. Верный пароль после
  ожидания входит (200), владельца запереть нельзя. Неверный после ожидания, как и раньше, получает
  `429 Too many login attempts`: текст ответа и аудит `rate_limit_block` не менялись. Имя, которого
  нет, задерживается так же, поэтому подсказки о существовании имени нет. Задержка считается
  отдельно для каждого имени. Лимит по IP прежний.
- Комментарий в `app/services/audit_service.py` больше не обещает «per-account lockout», а описывает
  задержку.
- Тесты: расписание задержек; нет задержки при 9 ошибках; верный пароль после 12 ошибок ждёт 4 с и
  входит; рост 1→30 с с новых адресов; другое имя не задето; несуществующее имя; лимит по IP. Есть и
  тест с настоящим ожиданием 1 с. Пока `admin` ждёт, `bob` с **того же** IP входит сразу, блокировка
  по IP не занята, а соседняя корутина продолжает тикать.
- Документация: `security.md`, FAQ, `first-run.md` (en/ru), строка Features в README.

## Что осталось и почему

| Что | Почему не сделано |
|---|---|
| Задержка не ограничивает параллельный подбор с пула адресов: N одновременных попыток ждут одинаково и проверяются вместе. Сверху такой подбор ограничивают только лимит по IP (5 за 15 минут на адрес) и размер пула. | Задача требовала задержку на попытку, которая не запирает владельца. Очередь по имени ограничила бы скорость, но тогда атакующий выстроил бы очередь перед владельцем, а это та же блокировка. Чтобы закрыть подбор полностью, нужен второй фактор или блокировка с разблокировкой из консоли. Это решение владельца. |
| Неверный пароль после порога отвечает `429`, а не `401`. | Ответ и запись в аудите оставлены как были, чтобы не менять API и существующие тесты. При желании это одна строка. |
| Предупреждение про `COOKIE_SECURE` срабатывает и в Docker за HTTPS-прокси (`WEB_HOST=0.0.0.0` внутри контейнера). | Изнутри контейнера нельзя отличить «за прокси» от «напрямую». Текст написан условно. |
| В однофайловой сборке PyInstaller (`deploy/main.spec`) `.env` ищется рядом с `main.py` во временной папке распаковки, а не рядом с `.exe`. | Так же устроены и пути к базам (`users.db` и другие); менять это — отдельная задача про сборку под Windows. Пользователям сборки остаётся `set ИМЯ=…`. |
| Docker, nginx и Caddy вживую не проверялись. | В этой среде их нет. Адрес шлюза (`172.18.0.1`) — пример; в документации описано, как найти свой. |
| Остальные пункты «Найдено, но оставлено» из `REVIEW_2026-11.md` (пределы стола по моделям, `.tmp` бэкапа, `break` в цикле опроса и другие). | Вне этой задачи. |
| `CHANGELOG.md` не тронут. | Релизы и записи в журнале изменений ведёт владелец. |

## Как проверял

```bash
pip install -r requirements.txt pytest httpx
python -m pytest -q                                   # 2986 passed
python -m pytest -q tests/test_hardening_2026_11.py   # 34 passed
cd docs-site && pip install -r requirements.txt && mkdocs build --strict
```

Живой запуск: копия проекта с `.env` (`WEB_HOST=0.0.0.0`, `WEB_PORT=8765`, `COOKIE_SECURE=1`,
`FORGE_TRUSTED_PROXIES=127.0.0.1,::1,not-an-ip`), `python main.py`. Вход проверялся Chromium из
Playwright по адресу контейнера в сети и через curl с `X-Real-IP` через `127.0.0.1`. Пароль и адреса
в этой проверке тестовые, в репозиторий не попали; скриншоты не делались.
