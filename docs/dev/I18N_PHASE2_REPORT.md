# Отчёт: английский перевод, второй этап

Ветка `claude/i18n-phase2` от `main` (2.1.0). Продолжение [I18N_REPORT.md](I18N_REPORT.md): закрыты
четыре пункта из его раздела «Что осталось на русском и почему».

## Коротко

* **Сделано.** Четыре пункта:
  * Telegram-бот говорит по-английски по настройке `telegram_lang` («Админ → Система → Telegram →
    Язык бота»). Сводка, длительности `5h30m`, уведомления, шаблоны по умолчанию и тексты HMS
    (английский оригинал Bambu по коду) идут через тот же словарь `en.js`, второго словаря нет.
  * CSV журнала печатей и CSV аудита отдают заголовки на языке панели.
  * `hms_catalog` скачивает у Bambu ещё и таблицу `lang=en`. Наружу по-прежнему уходят только
    префикс модели, язык и версия.
  * В английском режиме `app.js` пишет `×1.00` и `01/11`. В русском — ни символа разницы.
* **Проверено.** Полный прогон зелёный. Живая проверка: настоящая панель на синтетической ферме
  и синтетическом журнале, Playwright в EN и RU. Проверены выбор языка бота в админке, сводка и
  уведомления бота, обе выгрузки CSV, даты и коэффициенты на «Печатях» и «Статистике», живое
  переключение RU ↔ EN. Обход первого этапа (`check_en.js`) тоже пройден.
* **Тесты: было 2952, стало 2975.** Плюс 23 новых: `test_i18n.py` +6, новый `test_i18n_bot.py`
  +12, `test_hms_catalog.py` +3, `test_jobs_api.py` +1, `test_audit_api.py` +1. Существующие тесты
  каталога HMS переписаны под третий запрос.
* **На русском осталось:**
  * данные пользователя: имена, задания, заметки и свои шаблоны Telegram;
  * в CSV — столбец «Описание»: это русский текст Bambu, сохранённый в журнале;
  * формат CSV для русского Excel: `;`, BOM, даты `дд.мм.гггг`;
  * коды, для которых у Bambu нет английского текста ни в одной таблице;

## 1. Telegram-бот на английском

### Переводчик `app/services/i18n.py`

* **Словарь** — `app.api.i18n.strings(lang)`, тот же блок `strings` из `app/web/i18n/<lang>.js`.
  Кэш на процесс, файл перечитывается при смене `mtime`.
* **`t(s, lang)`** — точный поиск по нормализованной строке, пробелы по краям сохраняются. Нет в
  словаре — строка как есть.
* **`tr(s, lang)`** — `t()`, а если точного перевода нет, известные куски внутри строки:
  * одна регулярка из всех кириллических ключей, длинные первыми, только на границах слов;
  * правило из `i18n.js`: если после подстановки больше 30 % букв остались кириллицей, строка
    возвращается как была (имя или незнакомый текст);
  * нужен для склеенных серверных текстов: `Ошибка печати 0300_400C`,
    `Klipper остановлен (shutdown): …`.
* **`duration(sec, lang)`** — `5ч30м` / `5h30m`. Единицы `ч`/`м` берутся из того же словаря.
* **`date(ts, lang)`** — `01.11 17:03` / `01/11 17:03` (как `en-GB` в панели), год добавляется,
  если он не текущий. Сейчас в текстах бота дат нет, функция — единое место для них, покрыта тестом.
* **`printer_error(text, status, lang)`** — `last_error` на языке бота:
  1. тексты Bambu заменяются английским оригиналом их кода. Источник —
     `app.api.i18n.live_texts()` по записям `status.notifications`: вендоренная таблица, затем
     каталог (п. 3);
  2. оставшиеся серверные слова переводятся через `tr()`;
  3. сообщения самой прошивки (Klipper, Creality) остаются как есть.
* **`template(values, key)`** — шаблон уведомления.
  * Свой текст администратора отправляется как написан, на любом языке бота.
  * Шаблон по умолчанию — на языке бота. Значение считается умолчанием, если оно пустое, равно
    русскому умолчанию (форма его сохраняет) или английскому.
  * Английское умолчание собирается из словаря: текст вокруг `{label}` (`✅ Print finished:
    {label}`), отдельного списка шаблонов нет.

### Где подключено

* `main.format_status_text(store, lang=None)`:
  * язык берётся из `settings_service.peek("telegram_lang")`, это кэш, база не открывается;
  * все русские слова сводки через `t()`, длительности через `duration()`, текст ошибки через
    `printer_error()`;
  * имена принтеров и заданий не переводятся.
* `poll_loop`: шаблоны трёх уведомлений через `template(scfg, …)`; текст ошибки в уведомлении
  тоже через `printer_error()` (HMS — английский оригинал).
* `TelegramReporter._establish_chat`: `"(нет данных)"` через `t()`.
* Язык меняется без перезапуска бота: сводка пересобирается на каждом цикле обновления,
  `apply_settings` на `telegram_lang` бота не перезапускает.

### Админка

* «Админ → Система → Telegram → Токен, чат, шаблоны и прокси» → поле **«Язык бота»**
  (`Русский` / `English`, оба `translate="no"`). Сохраняется на лету, как остальные поля раздела.
* Подсказка: «Сводка, уведомления и шаблоны по умолчанию. Свой шаблон бот шлёт как написан.»
* Поля шаблонов показывают то, что бот отправит: при английском боте умолчания видны
  по-английски, свой текст — как есть.
* Проверка: `telegram_lang` должен быть `ru` или кодом файла словаря, иначе 400.

## 2. CSV журнала печатей

* Кнопка «⇩ Выгрузить» в английской панели добавляет к ссылке `&lang=en`. В русской ссылка не
  меняется ни на символ.
* Сервер берёт заголовки из словаря через `app.services.i18n.t()`:
  * `Printer;Model;Job;Start;End;Plan, min;Actual, min;Pauses;Paused, min;Offline, min;Result;Code;Description;Layers`;
  * слова столбца «Результат» тоже из словаря: `Successful`, `Cancelled`, `Power loss`, …
* Неизвестный `lang` даёт русский файл, слишком длинный (больше 8 символов) — 422.
* Та же кнопка на вкладке «Действия» выгружает аудит. Ему тоже передаётся `lang`, заголовки:
  `Time;User;Action;IP;Browser`.

## 3. Тексты HMS из каталога Bambu на английском

* `hms_catalog` раз в сутки скачивает на каждый префикс модели третью таблицу:
  `query.php?lang=en&d=<P>[&v=<ver>]`.
  * Кэш — `data/hms/text_en_<P>.json`, рядом с `text_ru_<P>.json` (не в git и не в бэкапах БД).
  * Версия — `text_en_ver` в `meta.json` и в `status()`.
  * Ответ 201 («не изменилось») и все лимиты (8 МБ, 60 с на загрузку, обрезка записей) общие.
* Наружу уходят только префикс, язык и версия (тест `test_only_the_prefix_lang_and_version_go_out`
  теперь видит 6 запросов на два прохода).
* **Переход со старого кэша.** После обновления английской таблицы ещё нет, префикс считается
  устаревшим. На следующем проходе таблицы действий и русских текстов отвечают 201 по своей
  версии, скачивается только английская.
* **Если английская таблица не пришла,** русская и действия работают как раньше. Ошибка видна в
  `status()`, и проход повторяется через час, как при любом сбое.
* В `app/api/i18n.py` `_english(src, code, model, prefix)` ищет сначала в вендоренной таблице, затем
  `hms_catalog.text(prefix, code, "en")`:
  * `asked_texts` получает префикс от `_catalog_lookup`, который нашёл русский текст;
  * `live_texts` — по `id` принтера (`prefix_for`), иначе по модели;
  * этим же пользуется бот.

## 4. Числа и даты, которые app.js пишет сам

* В `i18n.js` два аксессора:
  * `I18N.dateSep()`: `"."` у русского, `"/"` у английского (так же, как `toLocale*` с `en-GB`
    в остальной панели);
  * `I18N.decimal()`: `","` у русского, `"."` у английского.
* Значения задаёт файл языка (`dateSep`, `decimal` в `register`), у третьего языка будут свои.
* В `app.js` 10 мест склейки «ДД.ММ» и одна десятичная запятая спрашивают аксессор так:
  `(typeof I18N === "object" ? I18N.dateSep() : ".")`. Затронуты:
  * `adClock`, `jobClock`, подписи дней `jobsDayBarsHtml`, `histPeriodText`;
  * `maintSinceText`, `maintTipText`, `nfSinceText`;
  * метки времени на canvas хронологии, `amsTipTime`, `fmtAuditTime`;
  * `jobNum` (`×1,00`).

  Без `I18N` (node-тесты `app.js`) и в русском режиме получается ровно прежняя строка.
* **Живое переключение.** Переводчик DOM строки без кириллицы не трогает, поэтому уже
  нарисованные `01.11` при переключении остались бы русскими до перерисовки. Теперь `app.js`
  слушает событие `forge-lang` (его шлёт `i18n.js`) и заново открывает текущий экран:
  `routeApply(routeNow(), true)`. Проверено на стенде в обе стороны.

## Что осталось на русском и почему

1. **Данные пользователя:** имена принтеров и заданий, заметки обслуживания, шаблоны Telegram,
   написанные администратором. Это не интерфейс, их не переводим по заданию.
2. **CSV:**
   * Столбец «Описание» — текст ошибки Bambu, сохранённый в журнале по-русски.
     * Закрыть можно обратным поиском `asked_texts` по каждому уникальному тексту выгрузки, с
       мемоизацией: в выгрузке до 20 000 строк.
     * Не сделано: задание просило заголовки.
   * Формат файла остаётся для русского Excel: `;`, BOM, даты `дд.мм.гггг чч:мм`.
     * Английский Excel с запятой как разделителем откроет такой файл одной колонкой. LibreOffice
       и Google Sheets спрашивают разделитель.
     * Менять разделитель по языку — отдельное решение владельца.
3. **Тексты Bambu без английского оригинала:**
   * кода нет ни в вендоренной таблице, ни в английской таблице каталога;
   * или каталог ещё не скачал `lang=en` (первый проход через 30 с после старта, затем раз в
     час до успеха).

   Такие строки остаются русскими в панели и в боте.
4. **Сообщения прошивок Klipper и Creality** показываются как их прислал принтер (обычно
   по-английски). Русские обёртки сервера («Ошибка Klipper», «Ошибка Creality») переводятся.
5. **Логи сервера** остаются как были: это не интерфейс. Например, `' (повтор)'` в
   `logger.info` — сборщик логи пропускает намеренно.
6. **Третий язык для бота.** Сервер примет любой язык, для которого есть файл словаря
   (`telegram_lang` проверяется по `app/web/i18n/*.js`). Но в выборе «Язык бота» сейчас два
   варианта, вписанных в `index.html`. Третий добавляется одной строкой `<option>`.
7. **Изменение в русском боте:** первое сообщение при пустой сводке теперь «(нет данных)»
   вместо «(no data)». Русский — основной язык исходников, английский берётся из словаря. На
   практике этого почти не бывает: при пустой ферме сводка — «Нет данных о принтерах».

Тонкости для переноса во внутреннюю версию:

* После обновления каталог HMS один раз докачает английские таблицы. Это +1 запрос на префикс в
  сутки и ~1 МБ на диске на префикс.
* `meta.json` получает поле `text_en_ver`. Старый `meta.json` читается без миграции.
* `app.js?v=122`: service worker кэширует статику по URL. `/i18n.js` отдаётся с ETag и
  `no-cache`, его версия не менялась.
* Новые ключи словаря лежат в конце блока `strings` в `en.js`. При слиянии с другой веткой
  конфликт возможен только в последних строках блока.
